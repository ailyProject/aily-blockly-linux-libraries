# @aily-project/lib-serial

Linux UART/serial initialization, I/O, input-buffer reset, and cleanup for the standalone CPython generator at `globalThis.Python`.

The package registers 12 block definitions but exposes only six general-purpose blocks in the toolbox:

`linux_uart_init`, `linux_uart_available`, `linux_uart_read`, `linux_uart_write`, `linux_uart_flush`, `linux_uart_close`.

The other six definitions are hidden compatibility types migrated unchanged from `@aily-project/lib-cybercam`:

`cybercam_uart_init`, `cybercam_uart_available`, `cybercam_uart_read`, `cybercam_uart_write`, `cybercam_uart_flush`, `cybercam_uart_close`.

`import serial` refers to the third-party **PySerial** distribution, not the Python standard library. Install it on the target with `python -m pip install pyserial`; npm installation does not install Python packages, configure device permissions, or enable UART hardware.

The public blocks use current PySerial APIs: `serial.Serial(device, baudrate)`, `in_waiting`, `read(size)`, `write(bytes_like)`, `reset_input_buffer()`, and `close()`. Public writes pass data through `_serial_payload`: `str` is UTF-8 encoded, while `bytes`, `bytearray`, and `memoryview` pass through unchanged; other types raise `TypeError`. `inWaiting()` and `flushInput()` are deprecated compatibility names; they remain only in the hidden legacy handlers and are not generated by toolbox-visible blocks. `flush()` waits for output transmission and must not be substituted for input-buffer reset. `read()` returns `bytes`.

Initialization leaves PySerial `timeout=None`, so `read(size)` blocks until the requested byte count is received. For a polling loop, query `in_waiting` first and read only that positive count.

The hidden `cybercam_uart_*` initializer is fixed to `/dev/ttyS2` and exists only so serialized legacy workspaces continue to load. New CyberCAM projects must use `linux_uart_init` with device `/dev/ttyS2`, followed by the public `linux_uart_*` blocks. Do not load the split serial package with an old aggregate `lib-cybercam` release that still registers the same six types.

CyberCAM UART2 uses TX2=IO11 and RX2=IO12. Check it with `gpio pins`; when disabled, run `sudo set-device enable uart2`, reboot with `sudo reboot`, and check again. Signaling is 3.3V TTL: cross TX/RX, share GND, set USB-TTL adapters to 3.3V, and do not connect the 4P cable's red 5V wire to a 3.3V device.

Sources: [01Studio CyberCAM UART](https://wiki.01studio.cc/docs/cybercam/basic_examples/uart/), [PySerial installation](https://pyserial.readthedocs.io/en/latest/pyserial.html#installation), [PySerial API](https://pyserial.readthedocs.io/en/latest/pyserial_api.html#serial.Serial), and [Python standard-library index](https://docs.python.org/3/library/index.html).
